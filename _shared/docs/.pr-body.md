# Fix runner-health-check workflow: add missing scripts, align guards with daemon pattern

## Problem

The Runner Health Check workflow references `scripts\assert_asus_target.ps1`, which does not exist anywhere in this repo (any branch) — so the step can never pass. Additionally:

- **0 runners are registered to this repo**, so the run dispatched after PR #1 was stuck queued forever (run 34014281841, now cancelled).
- The assert throws on LENOVO hardware, and the health-check (unlike the canonical daemon workflow) set no `EKA_BYPASS_MANUFACTURER_CHECK`.
- The Firebase auth-test step hard-fails when `FIREBASE_KEY` is absent — and this repo has **no secrets configured**.

## Fix

- Add `scripts/assert_asus_target.ps1` + `scripts/silent_console.ps1` (mirrored from urgaa-eka/eka-agent, which this workflow was originally mirrored from per commit 22cdaf8).
- Run the assert with `EKA_BYPASS_MANUFACTURER_CHECK: '1'` — matching the canonical daemon pattern in eka-agent's `eka-agent-daemon.yml`.
- Missing `FIREBASE_KEY` now logs a skip line instead of throwing; auth test runs only when the secret exists.
- Invoke the assert via the workflow's `powershell` shell (not a nested inline `powershell.exe` call).

## Verification

- Both scripts parse-clean under `[System.Management.Automation.Language.Parser]::ParseFile`.
- Workflow YAML validated with PyYAML.
- Live smoke test on the runner host (G4G-LAPTOP, LENOVO 82KA): `assert_asus_target.ps1` with bypass exits 0 with expected output.

## Note

A runner must be registered to this repo before this workflow can ever execute (currently total_count = 0). Registering one is out of scope — this PR makes the workflow correct for whenever that happens.
